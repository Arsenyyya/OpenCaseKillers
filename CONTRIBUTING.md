# Разработка

Начните с README и docs/README.md. Для локальной проверки нужны Python3.12+ и PostgreSQL из Compose. `make demo` даёт сквозной путь, `make check` — lint/format/schema drift/все тесты, `make check-wheel` — установку пакета вне checkout.

API и CLI используют одну application-логику. Изменения доменных состояний должны сохранять product scope, current revision, tombstones, idempotence и fencing. Модель не получает write-tools и не назначает роли/IDs. Для нового формата компании изменяйте ограниченный адаптер и проверяйте его контракт локальным сервером.

Исторические Alembic-файлы после0.2 заморожены. Для новой схемы добавьте миграцию и проверку upgrade на настоящем PostgreSQL; не заменяйте исторический DDL импортом текущей Base.metadata. Runtime-роли не должны становиться владельцами или обходить RLS.

При изменении контрактов выполните `make schemas` и закоммитьте exports. Новые поведенческие тесты проверяют пользовательский инвариант или реальную гонку, а не только повторяют реализацию. Mock/fixtures не являются независимой оценкой Qwen.

Не коммитьте `.env`, `.local`, credential files, private keys, caches, реальные обращения и данные компании. Для примеров используйте явно синтетический набор. Проверьте safe context и wheel перед публикацией. Реальные подключения/production deployment требуют отдельно предоставленных компанией endpoints, прав и политики хранения.

PR должен объяснять проблему и результирующее поведение, содержать выполненные проверки и реальные ограничения. CI выполняет те же Makefile-команды; его артефакты ограничены JUnit и проверенным wheel.
